    import { formatError } from './error-formatter.js'

    export const errorHandler = createMiddleware<ForgeEnv>(async (c, next) => {

<threat_model>

## Trust Boundaries

| Boundary                             | Description                                                                                                          |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------- |
| Error input → Problem Details output | Error objects from application code are converted to Problem Details — error messages may contain user-supplied data |
| Error handler → HTTP response        | Generated Problem Details served over HTTP — error messages could leak internal details                              |

## STRIDE Threat Register

| Threat ID | Category               | Component          | Disposition | Mitigation Plan                                                                                                                                                                                                                                                                                     |
| --------- | ---------------------- | ------------------ | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-02-04   | Information Disclosure | error-formatter.ts | mitigate    | Error messages from `Error` instances may contain stack traces, file paths, or SQL queries. Add JSDoc warning that `formatError` exposes `error.message` verbatim. Recommend users configure a `detailMapper` option in production to sanitize internal details.                                    |
| T-02-05   | Information Disclosure | error-handler.ts   | mitigate    | The error handler returns `error.message` directly. In production, internal error details should not leak to clients. Add optional `isProduction` parameter to `errorHandler` factory that replaces detail with generic message for 5xx errors. Default to `false` (development mode, full detail). |
| T-02-06   | Spoofing               | error-types.ts     | accept      | Problem Details `type` field is a URI reference — users control what URI they set. No validation needed as RFC 9457 allows any URI. Extension members (`[key: string]`) are user-controlled.                                                                                                        |

</threat_model>
