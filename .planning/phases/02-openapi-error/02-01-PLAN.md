<threat_model>

## Trust Boundaries

| Boundary                      | Description                                                                                     |
| ----------------------------- | ----------------------------------------------------------------------------------------------- |
| Schema input → OpenAPI output | Zod schemas from user code are converted to OpenAPI objects — no execution, pure transformation |
| Route metadata → API consumer | Route metadata is read-only introspection — no mutation of app state                            |
| OpenAPI doc → HTTP response   | Generated OpenAPI JSON served over HTTP — no secrets or credentials in document                 |

## STRIDE Threat Register

| Threat ID | Category               | Component   | Disposition | Mitigation Plan                                                                                                                                                                              |
| --------- | ---------------------- | ----------- | ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-02-01   | Tampering              | schema.ts   | accept      | Pure function transforming Zod to OpenAPI schema — no side effects, no external I/O. Input validation handled by Zod's own type system.                                                      |
| T-02-02   | Information Disclosure | docs.ts     | mitigate    | `serveOpenAPIDoc` serves OpenAPI spec publicly — add JSDoc warning that users should protect the endpoint in production (e.g., behind auth middleware). No secrets stored in generated docs. |
| T-02-03   | Spoofing               | response.ts | accept      | Response builders are pure data constructors — they don't authenticate or authorize. Consumers are responsible for setting correct status codes.                                             |

</threat_model>
